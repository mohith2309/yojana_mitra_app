## 2024-05-18 - Prevented information leakage in API error responses
**Vulnerability:** The API gateway previously returned raw upstream service (NVIDIA and Data.gov) error responses (including status codes and full response body) directly to the end client in `HTTPException(detail=response.text)`. This could expose internal network architecture, credentials, parameter names, or proprietary upstream server details to an attacker.
**Learning:** Returning `response.text` unmodified acts as an information leak and allows attackers to map internal proxy interactions. It also breaks the security principle of "fail securely", which dictates error states should not yield any useful reconnaissance data.
**Prevention:** Implement strict server-side logging (`logger.error(...)`) for all upstream HTTP failures to ensure developers retain debug visibility, while consistently returning generic errors (like "Upstream service error") with neutral status codes (like 502 Bad Gateway) to clients.
